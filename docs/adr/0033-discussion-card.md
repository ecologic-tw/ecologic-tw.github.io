# ADR-0033 可列印的討論引導卡

- 日期：2026-09-29
- 狀態：接受（2026-09-29，@Wang-Yi-Zhang）
- Decision Owner：@Wang-Yi-Zhang
- Review Point：發布後有至少一次實際在課堂、座談或會議使用（或一位試讀者印出試用）時，檢視：兩頁是否夠用、黑白列印是否清楚、哪些段落沒人用；再決定是否擴充其他引導卡（例如「給老師的 15 分鐘活動」）

## 背景
[SDD 13](../sdd/13-interaction-roadmap.md) §4 規劃「討論引導卡」：把網站的溝通方法帶到線下的課堂、社區座談與工作會議，排在綜合挑戰（ADR-0032）之後。

網站目前的溝通方法散在不同地方：
- 圖鑑卡的「善意回應法」
- 情境題的「換個位置想」（ADR-0029）
- 「善意詮釋與鋼人論證」卡

線下使用者需要一張能印出來、放在桌上的整理。另外，SDD 13 §5 的「分歧的種類」也還沒有概念卡，引導卡的反面需要它。

目前網站沒有任何列印樣式，內容集合只有 `entries`、`scenarios`、`terms`、`updates`。

## 決策
1. **頁面**：新增 `/toolkit/discussion/`，一張 A4、正反兩面。
   - **正面「回應之前」**：
     - 三步回應：確認理解 → 找共同點 → 提問。
     - 換個位置想：「如果我是他，我在擔心什麼？」然後用問的確認。
     - 常見陷阱：稻草人、人身攻擊、假兩難、草率概括、謬誤謬誤，各一句說明與一句善意回應。
   - **反面「分歧在哪裡」**：
     - 分歧的四種類型（事實、價值、定義、利益）與對應的處理方式。
     - 主持人提醒：對事不對人、允許說「我不知道」、把爭點寫在白板上。
   - **頁尾**（螢幕與列印都顯示）：網站網址、CC BY-SA 4.0 標示、「非官方立場」聲明。
2. **新內容集合 `toolkit`**：`src/content/toolkit/zh-TW/*.md`。
   - 讓非工程師可以編輯文字，並走既有審核閘門：只發布 `reviewed`，AI 起草一律 `draft`、`aiAssisted: true`。
   - frontmatter 沿用共用審核欄位（`status`、`reviewers`、`updated`、`published`、`aiAssisted`、`contributors`、`sources`），另有 `id`、`title`、`summary`。
   - 本文固定兩個段落：`## 正面：回應之前`、`## 反面：分歧在哪裡`。建置期檢查兩段都存在，列印時反面從新的一頁開始。
   - 引導卡本身不新增知識主張：每個陷阱連到對應的圖鑑卡，定義以圖鑑卡為準；有事實主張時附來源。
3. **列印**：用 `@media print` 與 `@page { size: A4 }`。
   - 列印時隱藏頁首、導覽、模式切換與頁尾連結，只留內容與授權頁尾。
   - 黑白也要看得清楚：不靠顏色區分，框線與粗體足以辨識。
   - 讀者用瀏覽器的「列印／另存 PDF」取得檔案；**不在建置時產生 PDF**，不新增工具鏈或依賴。
4. **同批起草概念卡「分歧的種類」**（`entries`，`kind: concept`，`draft`）：
   - 說明事實、價值、定義、利益四種分歧，以及各自通常怎麼往前走。
   - 界線模糊時（例如定義與價值）說明理由，不把分類當成定論。
   - 不屬 12 §5 的心理學內容，不需心理學背景審核者；來源由 AI 找出後標「待查證」，由人工核對。
   - 引導卡反面連到這張卡；卡片發布前，引導卡不能發布。正式建置不含草稿頁，建置產物的站內連結檢查會擋下連到草稿的連結。
5. **入口**：`/guide/` 圖鑑總覽與 `/about/` 關於頁各加一個連結「討論引導卡（可列印）」。不放進頁首導覽。
6. **工具與檢查**：
   - `npm run review` 支援 `toolkit`。
   - 內容檢查涵蓋 `toolkit`：兩段落、圖鑑卡連結存在且已審、殘留 `**` 的粗體檢查。
   - sitemap 與建置產物檢查納入新頁面。
7. **更新紀錄**：發布時在同一個 PR 的 `updates.yaml` 加一則 `kind: feature`。
8. **SDD 同步**：13 §4 連到本 ADR；03、04、06 於實作時更新。

## 依據的資訊與假設
- 假設：一張兩面的紙本整理，比請參與者上網更容易在線下場合使用；主持人可以自己印。
- 假設：用瀏覽器列印已足夠，不需要在建置時產生 PDF。Chromium、Firefox、Safari 都支援 `@page` 的 A4 尺寸與 `break-before: page`，但各瀏覽器的邊界與字型略有不同。
- 「分歧的種類」四分類是教學用的簡化，學術上的分類方式不只一種；卡片需寫明這一點。

## 已知風險
- **列印版面在不同瀏覽器超過兩頁**：驗收時以 Chromium 列印預覽檢查；e2e 用 Playwright 以列印媒體產生 PDF，確認頁數不超過 2 頁（只在測試中產生，不進建置產物）。
- **引導卡與圖鑑卡的說法不一致**：引導卡只放一句摘要並連到圖鑑卡；圖鑑卡修訂時，審核者一併檢查引導卡。
- **被當成「標準話術」**：正面加一句「這些是幫助理解的提問，不是讓對方同意的技巧」，與 ADR-0029「理解不等於同意」一致。
- **新集合增加維護成本**：先只有一張引導卡；Review Point 再決定是否擴充。

## 考慮過的選項
- **寫死在 Astro 頁面裡**：程式最少，但內容不走審核閘門，非工程師也難以修改。
- **在建置時產生 PDF**：下載方便，但需要新的工具鏈與依賴（紅線 8），也可能與網頁內容不同步。
- **放進 `entries` 當成一種卡別**：可沿用現有頁面，但引導卡不是知識概念，也不需要小檢核與收集；混在圖鑑裡會干擾「點亮圖鑑」。
- **放進頁首導覽**：比較顯眼，但頁首已有五個項目；先放在圖鑑總覽與關於頁，視使用情況再調整。

## 後果
- 新增一個內容集合、一個頁面、一份列印樣式、一張概念卡草稿。
- 審核工具、內容檢查與 sitemap 需要支援新集合。
- 需要以下測試：
  - 單元測試：schema、段落檢查、參照檢查。
  - e2e：頁面顯示、列印媒體下隱藏導覽、PDF 頁數不超過 2、淺色與深色 axe、草稿不發布。

- 新增內容集合 `toolkit`，不採寫死在頁面裡的做法。

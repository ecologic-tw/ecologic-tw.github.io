# ADR-0029 「換個位置想」段落與善意詮釋概念卡

- 日期：2026-09-28
- 狀態：提議
- Decision Owner：人類維護者
- Review Point：4 題試行內容完成人工審核並有至少一位試讀者回饋後，決定是否以 `npm run scenario -- edit` 分批補進已審題目

## 背景
使用者希望網站幫助讀者學習「溫柔」：理解對立的一方，促成有效溝通。現有情境題的解說指出推理問題，但較少引導讀者站到說話者的位置思考。網站已有「善意詮釋」名詞與非暴力溝通卡，但沒有說明「理解不等於同意」、鋼人論證與「用提問確認」的概念卡。

## 決策
1. 情境題本文新增**選填**段落 `## 換個位置想`，作答後顯示在解說之後，附固定提示：「理解不等於同意。試著想想對方在意什麼，再用提問確認，而不是替對方下結論。」沒有這段的題目不顯示任何區塊。
2. 寫作規則（補充 08）：
   - 以「如果你是……」分別站到說話者與其他當事人的位置，用「可能」「也許」表述，不推論人格或動機。
   - 結尾給一句「可以怎麼問」，引導用提問確認（問比猜更準確）。
   - 不替推理錯誤辯護；對照題也可使用，說明推理正確仍可照顧不同人的需要。
   - 不要求受傷害或被攻擊的一方更有禮貌。
3. 新增 `concept` 卡「善意詮釋與鋼人論證」（draft），說明理解不等於同意、溫柔不等於放棄事實、補上的理由要用提問確認。
4. 試行範圍：只補 4 題草稿（daily-020、cons-018、cons-019、cons-020）。已審題目不直接修改，採用後以 `npm run scenario -- edit` 走提案與審核流程，依 ADR-0025 視為「補充」。
5. `npm run scenario -- new` 的本文範本加入空白的 `## 換個位置想`。

## 依據的資訊與假設
- 假設：固定出現在解說之後、篇幅短小的反思，比另開題型更容易讓讀者養成習慣。
- Eyal、Steffel 與 Epley（2018）的實驗指出，直接詢問比想像對方觀點更能準確理解對方；原文與適用範圍待人工核對。

## 已知風險
- 流於說教或替錯誤開脫 → 固定寫作規則，審核時確認沒有為謬誤辯護。
- 推測當事人心理，違反 08「不診斷他人」→ 只用「可能」描述處境與擔心，並以提問收尾。
- 概念卡含心理學研究主張 → 依 SDD 12 §5，需具心理學背景的審核者確認後才可發布。

## 考慮過的選項
- 另開「換位思考」題型：互動性較高，但需要新的判定規則與 schema，先以段落試行。
- 寫成 frontmatter 欄位：結構較嚴格，但 Markdown 段落可放粗體、名詞標記，也便於非工程師撰寫。

## 後果
情境題頁多一個選填區塊；內容 schema 不變（段落由 `scenario-sections.ts` 切分）。新增一張概念卡與對應測試。

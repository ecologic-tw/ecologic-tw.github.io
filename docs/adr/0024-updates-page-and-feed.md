# ADR-0024 更新紀錄頁與 Atom 訂閱源

- 日期：2026-09-27
- 狀態：接受（2026-09-27，@Wang-Yi-Zhang）
- Decision Owner：@Wang-Yi-Zhang
- Review Point：上線後第一次新增內容批次時，檢查頁面與訂閱源是否如預期列出；半年後依回饋表單意見決定是否需要「本機新標記」（原規劃第 2、3 項）

## 背景
內容會陸續新增，但網站沒有讓使用者得知更新的方式。紅線排除了推播（需伺服器與金鑰）、電子報（需蒐集 Email）與追蹤；八角框架排除「限時」「別錯過」等黑帽手法。

## 決策
1. 內容（圖鑑卡、情境題、名詞）新增選填欄位 `published`：**首次發布日期**，不隨勘誤變動；`updated` 仍記錄最後修改日。
2. `npm run review`（`scripts/mark-reviewed.ts`）將草稿標為 reviewed 時，若尚無 `published`，自動填入當天日期；已有者不覆寫（退回草稿後重新審核仍保留首次日期）。
3. 新增內容集合 `updates`（`src/content/updates/zh-TW/updates.yaml`），由維護者手寫功能更新、重要勘誤等說明。
4. 新增 `/updates/` 頁：依月份列出手寫更新與新上架內容；沒有 `published` 的既有內容歸為「首批內容」，只顯示數量，不推測日期。
5. 新增 Atom 訂閱源 `/updates/feed.xml`：僅含 reviewed 內容與手寫更新，最多 50 筆；草稿建置輸出空的訂閱源。各頁 `<head>` 加上 `rel="alternate"` 連結，頁尾加入「更新紀錄」。
6. 文案用邀請語氣（「新上架」「更新紀錄」），不使用「最新！」「別錯過」等字眼，不顯示倒數或期限。

## 依據的資訊與假設
- RSS／Atom 閱讀器由使用者自行選擇與訂閱，本站不知道誰訂閱，符合無追蹤原則。
- 靜態 XML 不需要腳本，不影響 CSP。

## 已知風險
- 維護者忘記寫手寫更新 → 新上架內容仍會自動列出；手寫更新只用於補充說明。
- 直接手改 status 而非使用 `npm run review` 時，可能漏填 `published` → 內容仍會發布，但只算在「首批內容」；審核指南提醒手動補上。
- 閱讀器快取造成更新延遲 → 可接受，不影響網站本身。

## 考慮過的選項
- 以 git 歷史推算首次發布日：建置環境需完整 git 歷史，且狀態變更不一定對應發布，不可靠。
- 沿用 `updated`：勘誤也會改動，會把修錯字誤判為新內容。
- 本機「新」標記與 `/me/` 提示：需要修改進度資料格式，列入後續（見 Review Point）。

## 後果
內容 schema 版本號提升；新增一個內容集合、一個頁面與一個 XML 端點；sitemap 與產物檢查同步納入。

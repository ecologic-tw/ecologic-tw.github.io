# ADR-0016 共用 AI 協作規範與跨工具交接
- 日期：2026-09-27
- 狀態：接受（2026-09-29，@Wang-Yi-Zhang）
- 決策者：@Wang-Yi-Zhang
- 回顧點：首次由 Codex 與 Claude Code 交接任務後，確認兩者都讀取同一份規範，且交接紀錄足以重現驗證結果

## 背景
既有開發指引集中在 `CLAUDE.md`，其他 AI 工具的使用者不容易找到共同規則。使用者要求將 Codex 納入現有規範，讓未來能使用不同 AI 工具接手。

## 決策
1. 將既有開發指引移至根目錄 `AGENTS.md`，作為所有 AI 工具共用的規範來源；原有八項紅線與社群文化要求完整保留。
2. 保留 `CLAUDE.md` 作為 Claude Code 入口，要求開工前完整閱讀 `AGENTS.md`；不另維護一份重複規則。
3. Codex 使用 `AGENTS.md`；其他工具若未自動載入，由使用者明確要求讀取。README 與 CONTRIBUTING 提供入口和可複製的開工提示。
4. 開工先核對工作目錄、Git 狀態、里程碑與相關 ADR；交接記錄任務、變更、驗證、風險及下一步，並保存於 PR、Issue 或 repo 文件，不依賴單一工具的聊天記憶。

## 依據的資訊與假設
- [OpenAI 官方文件](https://learn.chatgpt.com/docs/agent-configuration/agents-md)說明 Codex 會載入 `AGENTS.md` 作為專案指示。
- 假設：接手工具能閱讀 repo 檔案；不能存取 repo 時，由使用者提供共用規範與相關文件。
- 本次只調整規範入口與交接流程，不變更紅線、審核權限或社群基本原則。

## 已知風險
- 工具未自動載入或忽略導讀時，可能漏讀規範；以明確開工提示與閱讀後摘要確認。
- 各工具各存一份規則容易失去同步；工具入口僅導向共用規範，新增工具時沿用此方式。
- 交接紀錄可能落後於程式；接手時須重新核對 Git 狀態與驗證結果。

## 考慮過的選項（含不同意見）
- 在 `CLAUDE.md` 與 `AGENTS.md` 複製完整規範：容易產生不一致。
- 只在 README 提及 Codex：缺少 Codex 可載入的專案規則入口。
- 保留 `CLAUDE.md` 為共用來源：仍以單一工具命名，不利未來加入其他工具。

## 後果
- 共用規則只維護於 `AGENTS.md`，相關文件與 Issue 範本同步更新引用。
- 不新增套件或服務；AI 仍不得自行擔任決策者、核准或合併 PR，內容仍須人工審核。

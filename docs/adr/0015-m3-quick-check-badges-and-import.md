# ADR-0015 M3：卡內小檢核、閱讀紀錄、徽章發放與進度匯入規則
- 日期：2026-09-26
- 狀態：接受（2026-09-29，@Wang-Yi-Zhang）
- Decision Owner：@Wang-Yi-Zhang
- Review Point：內容第一次大量改為 reviewed 時（確認徽章條件在實際題數下合理），或收到匯入相關的問題回報時

## 背景
M3 要實作個人圖鑑、徽章與匯出匯入（04、05、07）。實作時發現：
1. 「圖鑑收藏家」要求點亮全部 22 張卡，但「收集」的定義是答對以該卡為正解的情境題（CONTEXT、05）。8 張思維定律與有效推論卡不會是任何情境題的正解，**依原定義永遠無法點亮**。02 規則 4 已寫明這類卡可「閱讀完並完成卡內小檢核」收集，但 schema 沒有對應欄位。
2. 「謬誤的謬誤」徽章要求「讀完謬誤謬誤卡」，進度資料沒有記錄閱讀的欄位。

## 決策
1. **卡內小檢核 `quickCheck`**（03 schema 新增選填欄位）：`question`、`options`（2–4 個）、`answer`（選項索引）、`explanation`。
   - `law`、`inference` 卡**必填**，確保「圖鑑收藏家」可以達成；其他卡別可選填。
   - 沒有 JavaScript 時以「看答案」`<details>` 呈現；有 JavaScript 時答對即點亮，答錯可再試，不記錄錯誤。
2. **閱讀紀錄 `read`**：進度新增 `read: string[]`，在圖鑑卡讀到結尾（結尾標記進入畫面）時記錄。只用於「謬誤的謬誤」徽章。版本號維持 1：舊資料與舊匯出檔缺這個欄位時視為空陣列。
3. **收集**：點亮的卡 ＝ 答對以該卡為正解的已發布情境題 ∪ 小檢核答對的卡（存於 `collected`），只計目前已發布的卡。
4. **徽章**：規則是純函式（`src/lib/badges.ts`），在「我的圖鑑」頁計算並寫回 `badges`；**已得到的徽章不收回**（內容日後下架或調整也一樣）。主題完成類徽章只看基礎題，且需要該主題至少有一題已發布。
5. **匯入**（07）：
   - 先看檔案大小，超過 100 KB 不讀取內容；以 UTF-8 位元組數計算。
   - JSON 解析後以 zod 嚴格驗證型別與長度上限，任何欄位不符就整份拒絕。
   - 未知欄位捨棄；id 只保留本站目前認得的，其餘略過並告知略過筆數。
   - 匯入前確認，匯入後**取代**目前紀錄（不合併）。
   - 檔案內的字串一律不顯示，畫面文字都來自本站內容。

## 依據的資訊與假設
- 已驗證：zod 解析 `__proto__` 鍵時會捨棄，不會污染原型；另以已知 id 過濾作為第二層防護（單元測試涵蓋）。
- 假設 1：以「結尾標記進入畫面」判斷「讀完」已足夠；它無法確認使用者真的讀了，但徽章本身沒有利害關係。
- 假設 2：匯入採取代而非合併，較容易理解，也避免合併規則的歧義。

## 已知風險
- 風險 1：小檢核題目是新內容，同樣需要人工審核；若題目本身有爭議，會直接影響「圖鑑收藏家」。
- 風險 2：題目下架後，已作答紀錄仍留在使用者瀏覽器；匯入時會被略過，平常則不影響顯示（只計已發布內容）。
- 風險 3：使用者誤按「清除」無法復原 → 以確認對話框提醒，並在頁面說明可以先匯出備份。

## 考慮過的選項（含不同意見）
- **把「圖鑑收藏家」改成只算謬誤與偏誤卡**：不需新欄位，但與 05「點亮全部圖鑑卡」及 02 規則 4 不一致。
- **閱讀紀錄改用停留時間**：需要計時，接近 05 禁止的「倒數計時」感受，且更難預測。
- **匯入時合併紀錄**：保留較多資料，但衝突處理（同一題不同答案、時間）複雜。

## 後果
- 03 的 schema 文件新增 `quickCheck`；8 張思維定律與有效推論卡新增小檢核草稿，需審核。
- 06 的 `progress.ts` 介面以本 ADR 與程式為準（見 06 更新）。

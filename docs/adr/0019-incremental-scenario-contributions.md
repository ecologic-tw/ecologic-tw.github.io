# ADR-0019 漸進情境協作與貢獻署名

- 日期：2026-09-27
- 狀態：接受（2026-09-29，@Wang-Yi-Zhang）
- Decision Owner：@Wang-Yi-Zhang
- Review Point：完成第一次多人接力投稿後，檢視工具步驟、待辦交接與署名是否清楚

## 問題與決策

正式情境草稿也需完整答案、選項、改寫、檢核清單與引用 ID。直接複製既有檔案還要手動處理編號及審核資料；修改已發布題目時，也容易誤留舊審核紀錄。這不利於只想貢獻構想、來源或試讀的人。

1. 在 `contributions/scenarios/` 保存可不完整的提案，不由網站或正式內容檢查載入。參與者可透過 Issue 或小型 PR 接力，只完成一部分並留下 `nextSteps`。提案不等於待上線題目。
2. 提供 `npm run scenario -- new|edit|check|promote`：建立提案、從既有題目複製修訂提案、列出待補項目、驗證後轉成正式 draft。自動分配新題號、拒絕覆寫既有提案；修改提案轉入前檢查原題是否已改變，避免覆蓋別人的新工作。
3. 貢獻者獨立記錄 `contributors: [{name, contribution}]`，只使用本人同意的公開名稱或筆名，不填私人聯絡資料；署名不等於人工審核。保留 `reviewers` 作發布門檻，AI 不填假人名、不把所有 commit 作者或 reviewers 自動當成貢獻者。
4. 轉成正式 draft 時沿用完整 schema、引用及內容安全檢查，清空舊版審核者；任何來源、爭議雙審及對照題比例要求均保留。未完成提案不影響正常網站建置。
5. 網站外部連結統一另開分頁／視窗，保留 `noopener noreferrer` 與「另開視窗」提示；共用元件降低漏改機率，正式產物檢查把關。內部導覽不變。

## 假設、風險與取捨

採 GitHub Issue／PR 接力，不新增後端、帳號系統、CMS 或依賴。提案未正式驗證不代表可以包含個資；貢獻指南與 Issue 模板仍要求虛構與公開署名同意。工具檢查不能取代人類判斷。轉入已發布題目的修訂會使該題回到 draft，須安排人工重審與比例檢查後才合併，避免意外撤下內容。

不放寬正式 scenario schema 以容納空答案，避免開發預覽和出題流程需要遍布「欄位可能不存在」分支。工具只增加一個協作入口，不自動發 PR、核准或合併。

## 後續修訂
- 2026-09-29（@Wang-Yi-Zhang）：已轉入的提案改為移到 `contributions/scenarios/promoted/` 保留，不和進行中的提案混在一起；`promote` 自動搬移，已轉入的名稱不能再建立新提案。原因：17 份提案全數轉入後，AI 搜尋題目文字時容易找到已過時的提案版本。

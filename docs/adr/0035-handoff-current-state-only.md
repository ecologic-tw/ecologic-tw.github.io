# ADR-0035 交接紀錄只保留目前狀態（修訂 ADR-0016 決策 4）

- 日期：2026-09-29
- 狀態：接受（2026-09-29，@Wang-Yi-Zhang）
- 決策者：@Wang-Yi-Zhang
- 回顧點：實施後 2026-10-31，檢查 `docs/handoff.md` 是否維持在 60 行內、接手的 AI 是否仍能只靠 handoff、里程碑與 PR 重現進度；若出現「歷史紀錄找不到」的實例，改採封存檔方案

## 背景
ADR-0016 決定交接紀錄保存於 PR、Issue 或 repo 文件，未指定時用 `docs/handoff.md`。實際上幾乎每個 PR 都在該檔頂端追加一節，4 天內累積 60 多節、528 行、約 80 KB（估計約 27K token）。README「接手前先看」要求核對交接紀錄，因此每個 AI 工作階段開工時會整份讀入；加上 AGENTS、CONTRIBUTING、CONTEXT、11 里程碑，開工前約 38K token。依目前速度，一個月後會超過 100K token。

問題不只在長度：
1. **過時狀態會誤導**：舊節寫著「76 項全為草稿」「分支 `codex/content-review-p0-p1` 尚未提交」等當時的狀態。接手者必須自己判斷哪些還成立，AI 可能當成現況。
2. **重複記錄**：同一件事同時寫在 handoff、PR 說明、11 里程碑、SDD 13 與 ADR 文末，每個 PR 要同步 3–4 處。
3. **合併衝突**：多個分支都在同一檔頂端追加，2026-09-27 的框架檢視已記錄同檔頂端衝突。

## 決策
1. **`docs/handoff.md` 只寫目前狀態**：固定分段為「目前工作區」「待人工決定」「近期日期」「下一步」「參考」，每次交接**覆寫**成最新狀態，不追加歷史。目標 60 行以內；已完成且已記入 PR 或里程碑的事項直接移除。
2. **每次任務的完整紀錄寫在 PR 說明**：PR 模板新增「交接」段（目標與範圍、實際驗證結果、未完成與待人工決定、下一步）。ADR-0016 要求的紀錄欄位不變，只改變存放位置。沒有 PR 的任務（例如只做評估）才寫進 handoff 的「目前工作區」。
3. **進度的唯一來源是 `docs/sdd/11-milestones.md`**：handoff 只連結，不重述里程碑內容。
4. **舊的交接紀錄從工作樹移除**，在新 handoff 的「參考」記下最後一個含完整歷史的 commit（`2205dba`，PR #83 合併後），需要時以 `git show 2205dba:docs/handoff.md` 查閱。
5. 同步修改 `AGENTS.md`「跨工具交接」、`CONTRIBUTING.md`「使用 AI 工具協作」、`README.md`「接手前先看」第 2 點及 PR 模板的文字（草案見文末附錄）。

## 依據的資訊與假設
- 假設：所有非評估型任務都經 PR 合併（main 有 ruleset 保護），PR 說明可長期在 GitHub 查閱。
- 假設：接手者需要的是「現在是什麼狀態」，歷史只在追查原因時才需要；追查時可從 PR、`git log` 與 ADR 取得。
- 本 ADR 不改變紅線、審核權限、交接紀錄的必要欄位，也不新增套件。

## 已知風險
- PR 說明不在 repo 內，GitHub 無法存取時看不到歷史 → 舊歷史仍可由 git 取得；重要決策本來就要求寫入 ADR。
- 覆寫時可能漏掉仍未完成的事項 → 覆寫前先比對上一版的「待人工決定」，未完成的保留；回顧點檢查是否有遺漏。
- 60 行只是約定，沒有自動檢查，可能再度變長 → 若回顧點時超過，再決定是否在 `check:docs` 加行數上限（屬程式變更，另行處理）。
- 刪除舊檔後，搜尋 repo 找不到某段歷史說明 → 若發生，改採選項 B（封存檔）。

## 考慮過的選項（含不同意見）
- **A. 維持現狀**：零成本，但上下文與誤導問題會隨時間惡化。
- **B. 舊紀錄移到 `docs/handoff-archive-2026-09.md` 封存**：歷史留在 repo 可直接搜尋；但 AI 用關鍵字搜尋時仍會找到過時狀態，而且每月都要切檔。若決策者偏好保留在 repo，這是可接受的替代方案（放在 `docs/` 同一層，既有相對連結不會壞）。
- **C. 每個任務一個檔案（`docs/handoff/2026-09-29-xxx.md`）**：沒有合併衝突，但檔案數快速增加，與 PR 說明重複。
- **D. 本 ADR 的方案（只寫目前狀態＋PR 說明＋git 歷史）**：開工讀取量固定、沒有過時狀態；代價是歷史需要到 PR 或 git 查。

## 後果
- AI 開工必讀量從約 38K 降到約 12K token，且不會隨時間成長。
- 每次交接改為「改寫 handoff＋填 PR 交接段」，不再追加長段落；里程碑仍是唯一的進度來源。
- ADR-0016 的決策 1–3 不變；決策 4「交接保存於 PR、Issue 或 repo 文件」由本 ADR 具體化。
- 同批精簡 `docs/sdd/11-milestones.md`：已完成的區段縮成一行並附 ADR 與 PR；並把 `DESIGN.md` 補進 `AGENTS.md` 文件地圖。

**README「接手前先看」第 2 點改為：**
> 2. 讀 `docs/handoff.md`（目前狀態），再核對 Git 差異及相關 Issue／PR；歷史紀錄在各 PR 說明。

**CONTRIBUTING「使用 AI 工具協作」最後一段改為：**
> 交接紀錄寫在 PR 說明的「交接」段；`docs/handoff.md` 只保留目前狀態，交接時覆寫（ADR-0035）。不要只保存在單一 AI 的對話中。


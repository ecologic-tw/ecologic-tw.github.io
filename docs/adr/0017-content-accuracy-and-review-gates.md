# ADR-0017 概念修正、來源與雙人審核閘門
- 日期：2026-09-27
- 狀態：提議
- Decision Owner：維護者（由人類確認）
- Review Point：P0／P1 修正版首次人工審核前，以概念正確性、來源適用範圍與拒絕不完整審核資料的測試重新檢視

## 背景
外部驗證指出同一律、充足理由律、機率鏈及對照題的概念偏差；名詞未套用審核欄位，來源與第二位審核者只依賴文件提醒。使用者要求修正 P0、P1。

## 決策
1. 修正定義、案例、小檢核與名詞；同一律以 `x = x` 表示，充足理由律獨立說明為有爭議的哲學原則，舉證責任另見名詞。保留卡片 id 與數量；`law` 類別顯示為「思維定律與哲學原則」，避免把所有卡都當形式定理。
2. 對照題的結論限於題幹提供的證據；補充調查限制與虛構資料說明。同步修正涉及相同問題的卡片與其他對照題。不當訴諸權威卡改用虛構鳥類族群判斷，分開概念練習與放生政策爭議。
3. 三種內容共用 `reviewers`、`sources`、`updated`、`aiAssisted`、`requiresSecondReview`。所有 `reviewed` 內容至少一項具非空書目的來源；來源可用 `supports` 說明支援的主張，不把文獻當成虛構情境數字的出處。
4. `requiresSecondReview: true` 的爭議內容發布前，至少兩個不同的 GitHub 審核帳號；空白與大小寫不同的同帳號不得充數。對照題雙審先設計、不啟用：依使用者目前只有一位維護者的指示，`src/lib/review-policy.ts` 的 `controlRequiresSecondReview` 預設為 `false`，一般對照題仍為一人；未來透過 PR 改為 `true` 後，`isControl: true` 也要求兩人。兩種要求取較高者，控制開關不會關閉爭議內容的既有雙審要求。
5. 人工標記工具支援重複 `--reviewer`、更新名詞 metadata，寫入前先驗證全部指定項目；一項失敗則整批不寫入。schema 只能檢查資料，無法證明帳號本人實際審核，PR 核准仍不可省略。

## 依據的資訊與假設
- SEP 的 Identity、Principle of Sufficient Reason 與 Informal Logic；AAPOR 調查指引；因果推論及偵測率研究（修訂內容的 sources 與人工檢查清單列出）。
- 假設：將最低來源要求套用到全部已審知識內容，比自動猜測哪些句子是領域事實更可靠；草稿可逐步補齊。
- 所有修改後內容仍為 draft，不代替人類審核，不執行正式標記。

## 已知風險
- 有來源不表示來源真的支持全文；人工須逐項核對，尤其研究地區、物種、時間與推論限制。
- 來源要求及既有爭議內容雙審可能延後發布。對照題雙審尚未啟用；未來啟用前需先補齊已發布對照題的第二審核者，以免建置被擋。
- 保留 `law` id 類別是相容性取捨，介面說明須清楚區分形式規則與哲學原則。

## 考慮過的選項（含不同意見）
- 只修文字、不改 schema：無法阻擋無來源或欠缺第二審核者的內容被標記。
- 自動把全部草稿標為 reviewed：違反人工審核紅線。
- 新增卡別與舉證責任卡：擴大 MVP 範圍；本次先用清楚的分類名稱與獨立名詞區分。

## 後果
- 更新 schema、人工標記工具、測試、SDD 與審核指南。
- 不新增依賴；P2 的參考資料 UI、連結排程檢查及覆蓋率報表另行處理。

# ADR-0010 採用《共好型自主敏捷社群指引》作為社群文化
- 日期：2026-09-26　狀態：接受
- Decision Owner：A4
- Review Point：2027-03 第一次角色檢視時，檢視指引是否被實際使用

## 決策
以 `docs/共好型自主敏捷社群指引.md`（邏生門版）為社群文化依據；行為準則、治理流程、ADR 與 Issue 範本依其設計。原通用版直接改寫為邏生門版。

## 改寫要點（原通用版與本專案的衝突及解法）
| 原文 | 問題／衝突 | 調整 |
|---|---|---|
| §2 公開承擔 | 與資安私下回報、個資保護衝突 | 資安與個資先私下處理，修復後公開去識別化紀錄 |
| §2 公開承擔 | 與匿名投稿、創始人不願具名衝突 | 公開的是角色與理由，以帳號署名，不要求真名 |
| §6 資源權 | 志工專案無預算，無法兌現 | 改為「透明的限制」 |
| §7 三層責任 | 規模過大 | 改兩層（個人、社群），出現穩定小組再加 |
| §8 最低層級決策 | 看似與 PR 審核閘門衝突 | 明確區分：提案者決定內容，閘門只檢查紅線與品質 |
| §10 不同意仍執行 | 志工無執行義務 | 改為「可不參與，但不阻撓」，異議記入 ADR |
| §15D 社群介入 | 無程序、無迴避、無申訴，易生隱形權力 | 新增處理程序與 `CODE_OF_CONDUCT.md` |
| §19–20 實驗證據 | 與 ADR-0008 不做流量統計衝突 | 證據來源限表單、自願測試、GitHub traffic |
| §23 輪替 | 未定期程 | 每半年角色檢視，創始期即開始，連任滿 2 年優先交接 |

## 依據的資訊與假設
- 假設：初期維護者僅 1 人，數年內成員會替換。
## 已知風險
- 制度對小社群可能過重 → 若角色檢視連續兩期無人參與討論，簡化流程。
- 外部觀察員尚未指定 → D 類事件涉及唯一維護者時無人可處理；M4 前需指定。
## 後果
取代 10-governance 原先「採用 Contributor Covenant」的規劃。

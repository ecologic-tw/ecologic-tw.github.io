# ADR-0012 標題字型自託管霞鶩文楷 TC
- 日期：2026-09-26
- 狀態：接受（2026-09-29，@Wang-Yi-Zhang）
- 決策者：@Wang-Yi-Zhang
- 回顧點：M5 Lighthouse 量測時；或 `dist/` 超過 50 MB 時

## 背景
04「視覺方向」要求田野手冊風格、手繪感，且字型自託管（紅線 2：不得使用外部字型 CDN）。中文字型檔動輒數 MB，需要一種不增加建置工具、瀏覽器又只下載用到字元的做法。

## 決策
- 新增依賴 `@fontsource/lxgw-wenkai-tc`（霞鶩文楷 TC，字型授權 SIL OFL 1.1，套件 MIT）。
- 只載入 400 字重（`@fontsource/lxgw-wenkai-tc/400.css`），僅用於標題、卡名與站名；內文用系統黑體、英名用系統襯線斜體，兩者不需下載。
- 字型經 Vite 打包到 `dist/_astro/`，同源提供，CSP `font-src 'self'` 不變。

## 依據的資訊與假設
- 套件依 unicode-range 切成 116 個 woff2 分塊；瀏覽器只下載頁面用到字元所在的分塊。實測首頁載入 8 個分塊。
- 假設 1：文楷的手寫筆記感符合「手繪感」與「步道同行者」的語氣，且標題字數少，分塊數量有限。

## 已知風險
- 風險 1：`dist/` 會包含全部分塊（woff2＋woff，約 11 MB）。GitHub Pages 上限 1 GB，影響在可接受範圍；若發生 Pages 部署變慢，會看到 upload-pages-artifact 步驟時間明顯增加。
- 風險 2：標題用字分散時，首次瀏覽需下載較多分塊，可能影響 Lighthouse Performance（M5 目標 ≥ 90）；屆時可改為建置期子集化（例如 fonttools），需新 ADR。
- 風險 3：字型載入前以系統楷體顯示（`font-display: swap`），可能出現短暫字型切換。

## 考慮過的選項（含不同意見）
- **Noto Sans TC 子集**（04 舉例）：可讀性佳，但與系統黑體差異小，無法帶出田野筆記的手寫感；若用於內文，下載量遠大於只用於標題。
- **建置期子集化（fonttools／subset-font）**：檔案最小，但需在 CI 加入 Python 或 wasm 工具，且每次新增標題用字都要重新產生；目前內容量不值得。
- **只用系統楷體**：零下載，但 Windows（標楷體）與 macOS 字形差異大、且標楷體在螢幕上顯得生硬。

## 後果
- 標題字型在各平台一致；新增頁面不需額外處理字型。
- 若日後要把文楷用在內文，須重新評估下載量並更新本 ADR。

# ADR-0026 首次貢獻與接力試行

- 日期：2026-09-27
- 狀態：提議（文件草案已備妥；尚未進行真人試走）
- Decision Owner：@Wang-Yi-Zhang（2026-09-28 承接；狀態維持提議，待決定試行安排）
- Review Point：首次真人試走後、擴大招募前，由承接者檢視卡住的位置、補充說明次數與整理者投入；若無人接力，先縮減任務而非擴大招募。

## 背景

[ADR-0019](0019-incremental-scenario-contributions.md) 已允許不完整提案，但新人仍需自行從里程碑判斷可以做什麼、交出什麼，以及提交後由誰接手。目前角色集中一人，增加投稿量可能同時增加整理負擔。[ADR-0023](0023-sustainability-and-contributor-value.md) 的合作與永續提案仍有自己的決策程序，本案不代表接受該提案。

## 決策（提議）

1. 在貢獻指南提供試讀、查證與技術修改三種入口，連到四張有範圍與完成條件的任務卡。
2. 沿用既有表單、Issue、PR 與情境提案工具；任務卡只是工作說明，不建立另一套即時看板。公開後由對應 Issue／PR 記錄認領與進度。
3. 將「個人貢獻完成」「待補充或待審核」「已發布」分開描述。試讀、來源查核、文字整理與技術檢查可分工，均不取代正式審核。
4. 接力者須本人同意承接，未有人承接時明示待接力，不承諾回覆期限。任務文件初版留在 repo，對外發布另由人類安排。
5. 先請一位自願參與者試走一張卡，再決定繼續、修改或停止。只記自願提供的粗略耗時、卡點與改善建議，不蒐集聯絡資料、不追蹤操作、不比較個人表現。

## 依據的資訊與假設

- 既有提案工具可保留半成品與待辦，無需新增套件或系統。
- 假設：有具體交付範例，比要求新人通讀更多文件更容易開始；尚未以真人試走驗證。
- 假設：限制為四個小任務能降低整理負擔；若補充往返增加，須縮減或改寫。
- 查核來源的專業難度不會因任務變小而消失，因此允許提交「未找到／不能確定」及查找範圍。

## 已知風險

- 投稿無人接手：新人可能誤以為未被接受。提交時明列待接力，整理者只承諾自己能做的部分。
- 把分工誤當審核：範例明示試讀與 AI 協助不構成人工核准；`reviewers`、爭議雙審與發布比例維持原規則。
- 任務卡過期：開始前核對里程碑及對應 Issue／PR；完成後由整理者關閉或更新入口，避免重複勞動。
- 文件增加負擔：新增文件只放任務與試走範例；正式規則仍連回原指南，不複製 schema 與指令手冊。

## 考慮過的選項（含不同意見）

- 只擴充 CONTRIBUTING：入口集中，但完整範例會讓首頁更長，採短入口加按需連結。
- 新增 CMS、看板或自動指派：目前人力與需求未驗證，先不增加維護成本。
- 直接大量公開新手 Issue：可能超出接力能力，先準備任務、完成一次試走再評估。

## 後果

新增 [首次任務卡](../review/first-contribution-tasks.md) 與 [接力及試走範例](../review/first-contribution-walkthrough.md)，入口放在 CONTRIBUTING；里程碑只勾選文件準備，真人驗證與本 ADR 的接受另列待辦。這不改變紅線、權限、角色資格或人工審核要求。

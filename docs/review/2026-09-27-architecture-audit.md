## 發現與建議順序

1. **P1：正式內容檢查未驗證必要本文段落。** `src/lib/content-checks.ts` 檢查 schema、引用與敏感文字，但沒有檢查 `## 情境`、`## 解說` 是否存在且非空。以記憶體副本清空 reviewed 的 cons-013 本文，或將情境標題改為「情境描述」，`checkContent` 均回傳零錯誤；頁面只取固定標題，會漏呈現內容。提案 promote 有這項檢查，直接編輯沒有。建議抽出共用本文驗證，讓內容檢查與提案工具使用；人工標記工具寫入前也應驗證整批候選內容。這是防護缺口，並非目前已有空白題目。
2. **P1：cons-013 仍將機率性推論稱為否定後件。** 第 45 行以「很有機會聽到／很可能不在」描述推論，不能直接等同必然條件句的演繹形式。建議分開說明演繹形式與未偵測證據的機率性判斷，避免暗示重複未偵測即可推出不存在。需人工審核修訂內容，本次未更改 reviewed。
3. **P2：圖鑑導航引用造成發布連動。** related、pairWith 與必要教學引用使用相同 reviewed 門檻。目前導航圖有一組 20 張卡互相可達；在記憶體中僅將 modus-tollens 退回 draft，就產生 5 個引用錯誤。若僅靠逐張退回來消除錯誤，會擴散到相依內容。建議評估將可選導航與必要語義依賴分開：必要引用維持門檻，可選導航於建置時過濾。需要 ADR 與人工決策，不宜逕自放寬所有引用。
4. **P2：全主題對照題比例與模式分流有成本衝突。** ADR-0022 明確決定所有已發布情境題共用分母，因此不是實作違反規格。日常目前 3/17；記憶體中加入 4 題同型的進階題後變成 3/21，檢查失敗，但基礎模式題目未變。建議在 ADR Review Point 比較各模式實際可見題目的比例與全站比例，再決定哪些需要阻擋發布，避免為發布進階題被迫新增基礎對照題。
5. **P2：篇幅報告不能直接代表基礎模式閱讀負擔。** `src/lib/content-quality.ts:87` 將 scenarioTexts 全部加入 basic，包括進階題 prompt、choices、notes；本文則按標題分類。目前報告文字確實說明按段落分類，但「基礎／進階」欄名容易被誤用。建議先釐清欄名是主文／延伸解說，或另外按 difficulty 與實際顯示階段統計；不要單靠字數判斷易讀性。
6. **P2：表達分層與文件同步仍有改善空間。** cons-008 仍只有情境與解說，沒有進階解說；可先保留核心判斷與必要理由，將延伸限制移至進階，但這是編輯判斷而非 schema 錯誤。里程碑第 63、65 行仍將已發布的進階題與訴諸傳統內容列為待人工審核，需維護者核對 PR #33 的審核紀錄後同步，AI 不代為認證人工審核。

## 架構判斷與待決定事項

Astro 靜態輸出、Markdown/YAML、共用 schema 與本機進度符合目前規模，未見需要引入後端或 CMS 的理由。主要成本在同一發布規則跨工具驗證不一致，以及導航、題型與全站配額相互牽動。優先補共用驗證，再處理引用與比例決策；不建議全面重寫。

進度只以題目 id 保存 correct、at（`src/lib/progress.ts:126`）。未來若同 id 的題幹或正解重大變動，舊作答仍會保留；可在實際出現這類修訂時評估內容版本與「題目已更新」提示，保留既有徽章。這是長期取捨，非目前已證實的資料損壞。

以上建議尚未成為 ADR。待人工決定：機率推論修訂措辭、哪些引用屬必要教學依賴、比例應在哪個範圍阻擋發布。下一步可先處理前兩項，所有 AI 修訂內容維持 draft，交由人類重新審核。

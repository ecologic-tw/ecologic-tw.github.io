# 第一次貢獻：四張任務卡

這是 [ADR-0026](../adr/0026-first-contribution-pilot.md) 的試行草案，核對基準為 2026-09-27 的 [里程碑](../sdd/11-milestones.md)。尚未建立對應招募 Issue，四張卡的接力者皆待承接；不表示有人承諾處理時限。

開始前先看里程碑是否已完成、搜尋既有 Issue／PR；已有討論就接續留言。公開任務後，以該 Issue／PR 為進度紀錄，不在本頁複製認領名單。表單投稿者可直接提交，整理者再核對是否重複。完成後由整理者更新對應待辦及本頁入口。

每張卡只要求一部分成果；可隨時停止，留下做到哪裡即可。提交格式與匿名限制見 [貢獻入口](../../CONTRIBUTING.md)，接力方式見 [範例](first-contribution-walkthrough.md)。

<a id="task-01"></a>
## 01：核對「訴諸傳統」的一項來源

- **問題**：里程碑記載現有 SEP 引用未討論訴諸傳統，需另找來源；這是待查證工作，不要求你先接受卡片寫法。
- **所需背景**：能閱讀邏輯學來源並分辨原文與自己的推論。無需 Git 或開發環境；可能需要英文閱讀能力。
- **材料**：[現有卡片](../../src/content/entries/zh-TW/appeal-to-tradition.md)、[來源審核指南](review-guide.md)、[寫作準則](../sdd/08-misuse-prevention.md)。
- **範圍**：只挑卡片的一個主張，找一項直接相關的原始或可靠學術來源；不重寫整張卡、不自行標記 reviewed。
- **本階段完成條件**：交出主張原句、書目或網址、章節／頁碼、原文支持範圍與限制。未找到也可交出查找範圍與未解問題，不編造來源或宣稱全文已讀。
- **交付位置**：既有相關 Issue；若沒有，使用「內容勘誤」範本，ID 填 `appeal-to-tradition`，或表單附「任務 01」。
- **接力需求**：內容審核者核對原文；整理者提出修訂並依既有指南安排重新審核。提供來源不代表已完成整張卡審核。

<a id="task-02"></a>
## 02：試讀一則修訂說明

- **問題**：里程碑仍列第一批修訂說明文字待人工確認，需要知道一般讀者是否理解改了什麼。
- **所需背景**：願意閱讀與描述疑問即可，無需知道謬誤名稱或操作 Git。
- **材料**：[修訂說明檔](../../src/content/updates/zh-TW/updates.yaml)，只讀 `cons-013-detection-inference` 這一則的 title 與 summary；不用理解 YAML 語法。
- **範圍**：用自己的話回答「原本說法有什麼問題」「現在怎麼說」；指出一處不理解的文字。沒有疑問也可以說明你如何理解。
- **本階段完成條件**：提交說明 ID、自己的理解、疑問或「未發現疑問」；不必提供改寫或判定邏輯正確。
- **交付位置**：「內容勘誤」Issue，ID 填 `cons-013` 並註明修訂說明 ID；或表單附「任務 02」。
- **接力需求**：文字整理者彙整歧義；內容審核者確認文字及分級。試讀不能直接勾選里程碑中的人工確認。

<a id="task-03"></a>
## 03：用手機走一次練習與回饋入口

- **問題**：M5 的手機實測尚未完成，需要一份具體操作觀察。
- **所需背景**：會用手機瀏覽網頁即可，不需要開發工具。
- **材料**：[正式網站](https://ecologic-tw.github.io/)、[M5 驗收](../sdd/11-milestones.md)。
- **範圍**：從首頁進入日常練習，選一題作答、展開解說，找到該題回饋入口；觀察文字是否被切掉、按鈕是否難點、回饋頁是否帶入題號。開啟入口即可，不需為測試送出空白回報。
- **本階段完成條件**：留下日期、題號、裝置大類與瀏覽器、操作步驟、預期與實際結果。截圖選填，請先遮掉個資；不收精確裝置識別資訊。
- **交付位置**：「功能建議／無障礙問題」Issue 或表單附「任務 03」；若入口本身壞掉，從 [貢獻指南](../../CONTRIBUTING.md) 使用另一管道。
- **接力需求**：技術貢獻者重現問題並修正；維護者彙整測試涵蓋範圍。單一裝置走通不等同完成全部手機、Lighthouse 或無障礙驗收。

<a id="task-04"></a>
## 04：試走環境指引並修正一處卡點

- **問題**：README 已有快速上手，但交接記錄尚未確認全新環境安裝體驗；先前本機也出現 npm 啟動器失效，需要分辨個別環境與文件問題。
- **所需背景**：基本終端機操作；提交修正 PR 需要 Git。只回報卡點不必完成 PR。
- **材料**：[README 環境準備](../../README.md#環境準備與快速上手)、[共用規範](../../AGENTS.md)。正式修改前依規範完成開工閱讀。
- **範圍**：在自己的副本按 README 走到啟動預覽；記下第一個卡點，若是文件缺漏，只修正一處。不要為了模擬新環境刪除既有工作或重裝整台電腦。
- **本階段完成條件**：交出系統、Node／npm 版本、執行指令與去識別化錯誤摘要；如無卡點，記錄實際走通範圍。修正 PR 另附修改理由與 `git diff --check` 結果。不要貼 token、完整環境變數或含私人路徑的整份日誌。
- **交付位置**：「功能建議／無障礙問題」Issue；確認文件問題後提出只改 README 的小型 PR，引用原 Issue。也可先交回報由他人接力。
- **接力需求**：維護者確認修正適用性；若涉及依賴或架構，另走 ADR。環境個案不能直接變成所有人的安裝要求。

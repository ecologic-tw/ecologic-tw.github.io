# 首次貢獻的接力與試走

本頁為 [ADR-0026](../adr/0026-first-contribution-pilot.md) 的文件草案。以下回報文字是 AI 撰寫的流程示例，尚未真人試走；不代表實際貢獻、審核或發布紀錄。

## 從一次試讀到發布

以 [任務 02](first-contribution-tasks.md#task-02) 為例：

1. **投稿**：參與者閱讀指定修訂說明，從既有 Issue 或表單提交下列資訊。到這一步，個人的試讀貢獻即可完成。

   ```text
   任務：02
   對象：cons-013-detection-inference（cons-013 的修訂說明）
   我讀到：「否定後件需要『一定會偵測到』的前提」
   我的理解：這裡在區分確定的推論與機率性的證據。
   我的疑問：我不熟悉「否定後件」，需要先去哪裡看說明？
   已完成：只試讀這一則說明，未查核來源或整題答案。
   希望接力：請判斷是否需補一句白話說明或相關連結。
   署名偏好：不列入公開貢獻者署名。
   AI 協助：無（實際投稿請依真實情況填寫）。
   ```

   GitHub 帳號與留言本身仍公開；不列署名不等於匿名。希望避免公開帳號可用表單，但表單投稿不保證個別回覆。

2. **補充**：有人願意接手時，在同一個 Issue／PR 寫明承接範圍，例如「我只整理白話表述，知識正確性仍待審核」。無人承接則維持待接力，不把任務重新丟回投稿者。轉貼表單內容前先去除個資，不推測姓名或公開未同意的署名。
3. **提出修訂**：整理者比較原文與建議，說明採用或不採用的理由。依 [ADR-0025](../adr/0025-revision-disclosure.md) 與 [審核指南](review-guide.md) 提出 PR；若同時修改情境內容，先使用 [修訂提案流程](scenario-contributions.md)。AI 起草的知識內容維持 draft，不能代填人工審核。
4. **人工審核**：實際審核者確認來源、推理、文字與修訂分級；爭議內容維持兩位不同審核者要求。試讀、找到來源、技術測試通過都不等於核准。更新說明本身目前沒有 status 欄位，不能把提交文字直接當作已審；合併前須確認其人工審核紀錄。
5. **發布與回覆**：由有權限的人依既有 PR 流程處理；AI 不核准或合併。部署成功且確認實際結果後，才記錄已發布與相關連結。若不採用或暫緩，記錄理由；部分貢獻仍可算完成。

## 接力時可以複製的紀錄

```text
對象／Issue／PR：
已完成的部分：
證據與限制（看過哪些原文、實際跑過哪些檢查）：
待補充／待審核的部分：
接力者：待承接（有人自願承接後再填）
署名同意與 AI 協助情況：
發布狀態：尚未確認發布
```

這是討論紀錄，不是新的內容 schema 或核准欄位；正式 `contributors` 與 `reviewers` 的用途見 [逐步協作指南](scenario-contributions.md)。

## 真人試走方式

由人類協調者邀請一位自願參與者選一張任務卡；先確認有人能接收結果，再安排試走。參與者可只做到提交、可中途停止，也可不提供時間資料。不要要求完成所有四張卡。

| 要觀察的事 | 自願記錄方式 |
|---|---|
| 能否找到適合的任務 | 選了哪張卡；找不到時停在哪裡 |
| 是否知道要交什麼 | 哪個完成條件需要補充解釋 |
| 能否交出部分成果 | 已提交／中途停止；卡點與管道 |
| 人工接力成本 | 整理者記補充說明次數、可選的粗略耗時與下一步 |
| 是否理解審核界線 | 請參與者說明交付後還有哪些事未完成 |

不用錄影、不追蹤點擊、不蒐集 Email、姓名或其他聯絡資料；公開摘要先去識別化，只保留自願提供的回饋。這些資料用於改善任務，不用來排名或評價個人。

首次試走後，由 ADR 的人類承接者記錄「繼續／修改／停止」及理由。驗收重點是能交付一份範圍清楚的成果、知道仍待哪些審核，且整理者能明確接手或標示待接力；能否完成網站發布是另一件事。若仍需大量解說，先縮小或重寫任務。AI 的連結與文件檢查只能算預檢，不勾選真人試走完成。

# 手機實測檢查表與紀錄

Lighthouse 與 e2e 以桌機瀏覽器模擬手機，下列項目需要真機確認。換裝置、改版或調整互動時可重複使用。對應 [M5 驗收](../sdd/11-milestones.md)、[NFR](../sdd/01-requirements.md) 與[任務卡 03](first-contribution-tasks.md#task-03)。

## 檢查項目
### A. 主要流程（必測）
1. 作答：首頁 → 日常練習 → 選一題 → 選答案 → 送出 → 展開解說 → 下一題。選項好點、不誤觸；對錯不只靠顏色。
2. 改寫練習：在「試著改寫看看」輸入。鍵盤不遮住輸入框與按鈕，畫面不亂跳。
3. 名詞說明：點內文的名詞按鈕。說明框不超出螢幕；點旁邊或「關閉」能關閉（手機沒有 Esc）。
4. 回報入口：點「這題有問題？回報」，表單或 Issue 帶入題號。開啟即可，不需送出。

### B. 模擬測不到的特性
1. 系統字級調到最大：文字不被切掉、按鈕不重疊、無橫向捲動（NFR-04）。
2. 行動網路首次開啟：字型載入前文字先以系統字型顯示，換字型時版面不大幅跳動。
3. 系統深色模式：對比清楚，對錯提示可辨。
4. 橫向畫面：頁首與作答區可用。
5. 上一頁：作答後回到題目列表，完成狀態已更新。

### C. 手機上容易出問題的功能
1. 基礎／進階模式切換；進階題 `multi`（核取方塊）與 `validity-soundness`（兩組單選）的點擊範圍。
2. `/me/` 匯出：能下載或存到檔案（iOS Safari 特別注意）。
3. `/me/` 匯入：能從檔案選擇器選到匯出的 JSON，進度一致。
4. 無痕／私密瀏覽：作答正常，關閉後不保留進度。
5. 清除進度：有確認步驟，清除後畫面同步。

### D. 選測
- 螢幕閱讀器（iOS VoiceOver／Android TalkBack）走一次 A1。
- 關閉 JavaScript，圖鑑、題目與解說仍可閱讀（NFR-07）。

### VoiceOver 在名詞處中斷（2026-09-28，調查中）
- **補充實測（2026-09-28）**：兩指下滑「全部朗讀」時，會跳過名詞、接續往下念。名詞文字本身沒被念出（`/guide/theories-of-truth/` 表格中的「命題」），句子少一個詞，屬內容遺失。
- **已排除**：不是缺少替代文字。`alt` 只適用於圖片；按鈕的無障礙名稱取自內文，建置結果為「命題」，標記正確。
- **推測**：按鈕帶 `popovertarget`，Safari 可能將其視為彈出式控制項，「全部朗讀」會略過這類控制項、只念文字與連結；單指逐項瀏覽仍會停在按鈕上。尚未證實。
- **確認方式**：開啟 VoiceOver，單指滑到名詞，聽朗讀角色是「按鈕」還是「彈出式按鈕」。
- **狀態**：2026-09-28 Decision Owner 決定暫緩，列為後續追蹤。
- **結構**：名詞是段落中的 `<button>`（開啟原生 popover）。iOS VoiceOver 逐項瀏覽時，段落中的互動元素會把段落切成三段：前文、「條件句，按鈕」、後文。段落內的連結也會這樣。
- **推測**：這是 VoiceOver 對行內按鈕的一般行為，不一定是程式錯誤。AI 無法在 Windows 上重現 VoiceOver，尚待實測者確認中斷的樣子：
  - 單指右滑時停在名詞、再滑一次能繼續 → 符合上述結構，屬預期行為。
  - 兩指下滑「全部朗讀」時在名詞處停止、不再往下讀 → 異常，需要進一步除錯。
  - 會讀出名詞說明框的內容 → 可能是 iOS 版本不支援 popover，說明框直接顯示在文中。
- **修復難度評估**（若推測成立，建議名詞留在段落中當一般文字，後接小型說明按鈕「命題的說明」；需改 `termElement`、CSS 與 SDD 04，難度低到中）：
  - 保留按鈕、只調整朗讀文字（例如補上「名詞說明」提示）：低，但無法避免段落被切開。
  - 名詞在文中改為純文字，各段或頁尾另列「本頁名詞」按鈕：中高，屬互動設計變更，需修改 SDD 04 並寫 ADR，且會影響明眼使用者的操作。
  - 以 iOS 專用的 `role="text"` 合併段落：不採用，非標準屬性，且會讓名詞按鈕無法被聚焦。
